# Распределённая система платежей

Проект разработан в целях изучения языка Go и микросервисной архитектуры. Он представляет собой распределенную платежную систему, состоящую из API Gateway и нескольких изолированных gRPC-сервисов, взаимодействующих асинхронно через брокер сообщений.

## Архитектура системы

![Схема](/diagram.svg)

### Основной сценарий взаимодействия:
1.  **Клиент** отправляет HTTP-запрос (например, на оплату или пополнение баланса) на API Gateway. Запрос должен содержать JWT-токен в заголовке `Authorization`.
2.  **API Gateway** валидирует JWT-токен, извлекает из него `user_id` и передает этот идентификатор во внутренние gRPC-сервисы.
3.  **Payment Service** принимает gRPC-запрос на создание платежа, сохраняет запись в PostgreSQL со статусом `pending` и отправляет событие `payment.init` в топик Kafka. Клиент сразу получает ответ `201 Created`.
4.  **Billing Service** считывает событие `payment.init` из Kafka, проверяет баланс пользователя в своей БД PostgreSQL и производит списание средств.
    * Если средств достаточно, списывает их и отправляет событие `payment.result` со статусом `success`.
    * Если средств недостаточно, отправляет событие со статусом `failure`.
5.  **Payment Service** обрабатывает событие `payment.result` из Kafka и переводит статус платежа в своей БД в финальное состояние (`success` или `failure`).

## Технологический стек

*   **Язык разработки:** Go
*   **Протоколы взаимодействия:** HTTP/REST, gRPC
*   **Брокер сообщений:** Apache Kafka
*   **Базы данных:** PostgreSQL (драйвер `pgxpool`, кодогенерация запросов через `sqlc`)
*   **Конфигурация:** cleanenv (переменные окружения и файлы `.env`)
*   **Логирование:** log/slog (структурированный вывод в JSON)
*   **Сбор и просмотр логов:** Grafana, Loki, Grafana Alloy

## Запуск проекта

Вся система разворачивается в Docker при помощи Docker Compose.

```bash
git clone https://github.com/tynou/backend-go.git
cd backend-go
docker compose up -d
```

Команда запустит базы данных, Kafka, стек логирования (Loki, Alloy, Grafana) и все микросервисы.

## Документация и тестирование через Swagger

Все эндпоинты API Gateway задокументированы с помощью Swagger. Можно тестировать сценарии авторизации, пополнения баланса и оплаты напрямую через интерактивный веб-интерфейс.

`http://localhost:8080/swagger/index.html`
